# Plan d'Analyse des Applications Odoo Restantes

## Contexte

5 applications Odoo ont déjà été analysées complètement (Accounting, CRM, Sales, Purchase, Project). Il reste **40 applications** à analyser selon la même méthodologie standardisée.

## Méthodologie Standardisée

Chaque application Odoo sera analysée avec **7 documents** :

1. **Logique Métier** (`00_logique_metier/`) : Modèles de données, règles métier, workflows, calculs
2. **Parcours Utilisateur** (`01_parcours_utilisateur/`) : Personas, scénarios d'usage, onboarding, points de friction
3. **UI/UX** (`02_ui_ux/`) : Vues (List, Kanban, Form, Calendar, Graph, Pivot), widgets, patterns navigation
4. **Intégrations Cross-App** (`03_integrations/`) : Dépendances, flux de données, mécanismes d'intégration
5. **Spécifications Opérateurs Miyukini** (`04_specifications_miyukini/`) : Architecture Opérateurs, Contrats d'Équipe, Mandats
6. **Guide Intégration COG** (`05_integration_cog/`) : Patterns WriteIntent/Mandates, exemples code pseudo-Rust
7. **Guide Implémentation** (`06_guides_implementation/`) : Architecture technique, schémas Rust, API, plan développement

## Processus d'Exécution d'une Tâche

Pour chaque application, le processus suivant sera suivi :

1. **Exploration initiale** :
  - Récupération `__manifest__.py` pour identifier dépendances
  - Exploration structure `models/` pour identifier modèles principaux
  - Exploration structure `views/` pour identifier interfaces
2. **Création structure** :
  - Création dossier `docs/market/competitors/Odoo/[App]/`
  - Création 7 sous-dossiers (`00_logique_metier/` à `06_guides_implementation/`)
3. **Analyse et documentation** :
  - Création des 7 documents selon méthodologie établie
  - Référence aux analyses précédentes (Accounting, CRM, Sales, Purchase, Project) pour cohérence
4. **Création index** :
  - Création `_index.md` pour l'application
  - Mise à jour `docs/market/competitors/Odoo/_index.md` principal

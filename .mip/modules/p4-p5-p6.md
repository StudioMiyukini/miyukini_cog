## P5 — Livraison, Test humain et validation (toutes classes)

**Agent** : Denis (livraison) + George (assistance test)

### Volet 1 — Présentation du livrable

1. Commit final si nécessaire
2. Push final sur la branche feature
3. Horodatage `p5_start` dans les métriques
4. Présenter le résumé :
   - Fonctionnalités implémentées
   - Fichiers créés/modifiés, lignes écrites
   - Tests passés (unitaires, intégration, globaux)
   - Anomalies détectées et corrigées
   - Instructions pour tester (commandes, parcours utilisateur)

### Volet 2 — Test humain

5. Horodatage `p5_test_start`
6. L'utilisateur teste le livrable
7. George fournit une checklist de test :
   - [ ] Build OK
   - [ ] Lancement de l'application OK
   - [ ] Parcours principal utilisateur fonctionne
   - [ ] Cas limites testés
   - [ ] Performance acceptable
   - [ ] UI conforme (si applicable)

### Volet 3 — Questionnaire de satisfaction

8. Horodatage `p5_test_end`
9. Denis présente le questionnaire :

```markdown
## Questionnaire de satisfaction — <titre>

### Conformité fonctionnelle
1. Correspond à votre demande ? (OUI / PARTIELLEMENT / NON)
2. Écarts constatés ?

### Qualité perçue
3. Code propre et compréhensible ? (1-5)
4. UI satisfaisante ? (1-5, si applicable)
5. Performance acceptable ? (1-5)

### Satisfaction globale
6. Score global (1-5) :
   1=Inacceptable, 2=Insuffisant, 3=Acceptable, 4=Bien, 5=Excellent
7. Commentaires libres :

### Verdict
- [ ] ACCEPTÉ — Merge vers main
- [ ] ACCEPTÉ AVEC RÉSERVES — Merge + corrections mineures
- [ ] REFUSÉ — Retour en correction (boucle MIP)
```

### Volet 4 — Décision

**Si ACCEPTÉ / ACCEPTÉ AVEC RÉSERVES** :
```bash
git checkout main
git pull origin main
git merge feat/<slug> --no-ff
git push origin main
# Tag si release :
git tag -a vX.Y.Z -m "description"
git push origin vX.Y.Z
# Nettoyage :
git branch -d feat/<slug>
git push origin --delete feat/<slug>
```

**Si REFUSÉ — Boucle MIP** :
- Logger l'intervention humaine (type `error_finding`, impact `major`)
- Incrémenter `mip_loops`
- **Si `mip_loops` ≥ 10** : suggérer de réduire le scope (invariant I-15)
- NE PAS merger — la branche feature reste
- Retour en P0 : Maria reprend au temps 1 avec le feedback utilisateur
- Le brief précédent sert de référence

**Alternative PR** : `gh pr create` — l'utilisateur merge manuellement.

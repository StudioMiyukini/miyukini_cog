## P5 — Livraison, Test humain & Validation (toutes classes)

**Agent** : Denis (livraison) + George (assistance test)

### Volet 1 — Presentation du livrable

1. Commit final si necessaire
2. Push final sur la feature branch
3. Horodater `p5_start` dans les metriques
4. Presenter le resume :
   - Fonctionnalites implementees
   - Fichiers crees/modifies, lignes ecrites
   - Tests passes (unitaires, integration, globaux)
   - Anomalies detectees et corrigees
   - Instructions pour tester (commandes, parcours utilisateur)

### Volet 2 — Test humain

5. Horodater `p5_test_start`
6. L'utilisateur teste le livrable
7. George fournit une checklist de test :
   - [ ] Build OK
   - [ ] Lancement application OK
   - [ ] Parcours utilisateur principal fonctionne
   - [ ] Cas limites testes
   - [ ] Performance acceptable
   - [ ] UI conforme (si applicable)

### Volet 3 — Questionnaire de satisfaction

8. Horodater `p5_test_end`
9. Denis presente le questionnaire :

```markdown
## Questionnaire de satisfaction — <titre>

### Conformite fonctionnelle
1. Correspond a votre demande ? (OUI / PARTIELLEMENT / NON)
2. Ecarts constates ?

### Qualite percue
3. Code propre et comprehensible ? (1-5)
4. UI satisfaisante ? (1-5, si applicable)
5. Performance acceptable ? (1-5)

### Satisfaction globale
6. Note globale (1-5) :
   1=Inacceptable, 2=Insuffisant, 3=Acceptable, 4=Bon, 5=Excellent
7. Commentaires libres :

### Verdict
- [ ] ACCEPTE — Merger vers main
- [ ] ACCEPTE AVEC RESERVES — Merger + corrections mineures
- [ ] REFUSE — Retour en correction (boucle MIP)
```

### Volet 4 — Decision

**Si ACCEPTE / ACCEPTE AVEC RESERVES** :
```bash
git checkout main
git pull origin main
git merge feat/<slug> --no-ff
git push origin main
# Tag si release :
git tag -a vX.Y.Z -m "description"
git push origin vX.Y.Z
# Nettoyage :
git branch -d feat/<slug>
git push origin --delete feat/<slug>
```

**Si REFUSE — Boucle MIP** :
- Logger intervention humaine (type `constat_erreur`, impact `majeur`)
- Incrementer `mip_loops`
- NE PAS merger — feature branch reste
- Retour en P0 : Maria reprend Temps 1 avec feedback utilisateur
- Brief precedent sert de reference

**Alternative PR** : `gh pr create` — l'utilisateur merge manuellement.

## P6 — Rapport final, Archivage & Capitalisation (T3+)

**Agents** : Arianne + Jean (refactorisation memoire)

### Volet 1 — Rapport final

Arianne compile les metriques et produit le rapport final.

**IMPORTANT** : Le rapport DOIT contenir la **trace d'execution** extraite du plan annote et les **metriques de consommation** agregees depuis les task-notifications et timestamps filesystem. Un rapport sans trace est INCOMPLET. Un rapport avec des estimations (`~`, `environ`) dans les sections metriques est NON CONFORME — voir `modules/metrics.md` regle 16.

Artefact : `.mip/reports/YYYY-MM-DD-<slug>-report.md` — **400 lignes max** (regle 17). Si depassement, decouper : `report.md` (index + scores + resume) + `report-trace.md` (trace d'execution detaillee) + `report-metriques.md` (tables consommation).
